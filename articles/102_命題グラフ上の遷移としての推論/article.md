# 命題グラフ上の遷移としての推論

**命題レベル・アテンションと人間による命題精錬を備えた論理IDEの構想**

Oct 1, 2026 · @山田喜三郎

## この記事について

LLMに論理推論をさせると、それらしいが途中で飛躍した答えが返ってくることがある。逆に昔ながらの記号的AIは厳密だが、「患者」と「対象者」が同じものだと教えるだけでも一苦労だった。この記事は、その中間を狙う一つの設計を考える。推論を「命題グラフ上の遷移」として表し、どの前提を使うかの **選択** はLLMとアテンションに任せ、規則の **適用** は従来のアルゴリズムで厳密に行う。合言葉は「演繹は確率付きでも厳密に、一致不一致はアバウトに」である。

道具立ては三つある。命題を単位にしたアテンションで前提を選ぶこと。複数の推論パスを並行して伸ばし、見込みの薄い枝を捨てること。そして人間が命題を採用・分割・条件付けして精錬し、署名付きの世界モデル（`.wm`）として貯めていくこと。

後半では具体的な道具の構想として、論理Lint（LLint）、論理IDE（LogicStudio）、世界モデル形式（`.wm`）を紹介する。この記事は実験結果を含まない構想論文なので、検証すべき仮説と課題は最後にまとめておく。

> この記事は、筆者が[SF小説『ASI (超人工知能) の作り方』](https://note.com/kisaburo_y/n/nc2b41349dfda) \[11\] で ChatGPT と交わした対話から生まれた構想を、あらためて整理したものである。

## 1. はじめに：サイバースペース・デブリと条件なき知識

知識は、適用条件を伴わないとき害になる。本稿の出発点はこの経験則である。

ルールベース機械翻訳の辞書に「upper：（靴の）甲皮（名詞）」という一項目を加えただけで、回帰テストが大きく崩れた事例がある。新しい語義は一般文書ではほとんど選ばれない。それでも候補として存在するだけで、品詞・構文・語義の候補数が掛け算で増え、解析全体の探索空間を変えてしまう。

同じ構造は情報検索にも現れる。「FFmpegを依存関係の問題なしに使いたい」という問いに対し、検索エンジンも生成AIも、パッケージ管理・コンテナ・ソースビルドといった多数派向けの解を先に返しやすい。求めていた「静的リンク版を一本落として実行する」という解は、その中に埋もれる。個々の情報は正しいが、目的に対しては進路を妨げる。本稿ではこれを **サイバースペース・デブリ** と呼び、次のように定義する。

> 適用条件を失った知識。目的の達成確率を上げずに、候補空間を乗算的に膨張させる情報。

ここから一つの命題が導かれる。 **選ぶ条件がない知識は、ないほうがましである。** 知識はif文とセットで初めて知識になる。

Transformerのアテンションは、このif文を手続きではなくベクトル空間で実現したものと見ることができる。文脈（Query）と各要素（Key）の内積が、「この文脈ならこの知識」という条件分岐の役割を果たす。生成AIは魔法ではなく、文脈依存の知識選択器である。

さらにLLMは構造化出力（JSON）を安定して生成できるようになった。これは、厳密な定義を持たない命題を計算機で扱えるようになったことを意味する。本稿は、この二つの事実を組み合わせ、推論を命題グラフ上の遷移として再構成する。

## 2. 関連研究

推論をグラフとして外在化する試みには長い系譜がある。この構想の新しさは個々の要素ではなく、選択と適用の分離、および人間が編集する世界モデルとの統合にある。

| 系譜 | 代表例 | 本提案との関係 |
| --- | --- | --- |
| 図式論理・証明構造 | パースの存在グラフ、ジラールの証明ネット \[7\]\[6\] | 推論をグラフの変形として扱う発想の源流 |
| 議論フレームワーク | Dung \[5\] | 主張と攻撃関係のグラフ。`.wm` 同士の衝突比較に近い |
| 確率論理 | Markov Logic Networks \[14\]、ProbLog \[4\] | 論理式に確率を付す。本提案の「確率付きの厳密な演繹」に近い |
| 微分可能な定理証明 | Neural Theorem Prover \[15\] | 証明探索の構造を保ち、記号の単一化だけを埋め込み類似度で行う。「一致はアバウト」と最も近い |
| 記憶へのアテンション | Memory Networks \[19\]、End-to-End Memory Networks \[17\] | 文単位の記憶へのマルチホップ・アテンション。命題レベル・アテンションの先行例 |
| グラフ上のアテンション | Graph Attention Networks \[18\] | 隣接ノードへのアテンション |
| LLMによる思考の探索 | Tree of Thoughts \[20\]、Graph of Thoughts \[1\] | 中間思考をノードとして分岐・統合・棄却する。ただし遷移規則もLLMが担う |
| 人間のフィードバック | 選好からの強化学習 \[3\]、RLHF \[12\] | 人間の判断で振る舞いを調整する。ただし対象は重み |

これらの多くでは、選択（どの前提を使うか）と適用（規則をどう当てはめるか）が、同じ学習済みネットワークの内部で混在している。また、知識は重みに溶けるか、固定されたオントロジーとして与えられる。人間が署名付きで編集し、差分を取れる世界モデルという位置づけは見当たらない。

## 3. 基本原理：演繹は厳密に、一致はアバウトに

中心にある原理は、次の一文に尽きる。 **演繹は確率付きでも厳密に。一致不一致はアバウトに。**

従来の記号的AIは両方を厳密に扱った。「患者」と「対象者」は別の記号であり、両者を同一視するにはオントロジーを先に書く必要があった。知識表現の研究は、この「意味の厳密な定義」で長く足止めされた。

逆にLLMは両方を近似で扱う。同義・類義の判定は得意だが、推論の各段階も確率的に生成するため、ときに論理が飛躍する。

ここでは、この二つを分ける。

- **一致判定（アバウト）** ：二つの命題が同じことを指しているか、ある規則の条件にこの命題が当てはまるか。これは埋め込み空間での近さで判定する。命題に厳密な定義は要らない。意味は文脈、すなわちベクトル空間が支える \[2\]。
- **演繹（厳密）** ：いったん「この命題はこの規則の前提に一致する」と判定したら、規則の適用そのものは崩さない。前提に付いた確率は結論へ引き継ぐが、推論規則は確率的にしない。

これは人間の認知に近い。「あの人は山田さんらしい」という認識は曖昧である。しかし一度「山田さんだ」と認識すれば、「山田さんは昨日この話をしていた」という推論は普通に追う。認識は確率的、推論は論理的である。

この分離により、JSON程度の緩い構造を持つ命題でも、推論の単位として十分に機能する。命題は人間が先に定義するものではなく、ベクトル空間から必要な分だけ切り出すものになる。

## 4. 命題グラフ上の遷移としての推論

推論の状態を「確信度付きの命題の集合」とし、推論の一歩を「規則の適用によってその集合に命題を加える遷移」とする。推論の全体は、この遷移が描く命題グラフである。

### 4.1 構成要素

- **命題ノード** ：JSONで表した命題。主語・述語・様相などの緩い構造と、埋め込みベクトル、確信度を持つ。
- **関係エッジ** ：causes、implies、requires、contradicts、instance\_of などの型を持つ。同じ命題を複数の推論が共有するため、全体は木ではなく有向非巡回グラフ（DAG）になる。人間向けの表示では木として見せてよい。
- **規則** ：前提パターンと結論パターン、そして **適用条件** の組。適用条件こそが、第1節でいう「選ぶ条件」である。

### 4.2 主ルーチン

主ルーチンはLLMではなく従来アルゴリズムが担う。

1. 初期命題群から、適用可能な規則の候補を集める（選択：第5節）。
2. 選ばれた規則を厳密に適用し、新しい命題を生成する（適用）。
3. 枝ごとに確信度と整合性を評価する。矛盾を含む枝は捨てる。
4. 上位k本の枝だけを残して展開を続ける（ビームサーチ）。
5. 停止条件（結論に到達、確信度が下限を下回る、深さの上限）で止める。

LLMは枝を生やす側であり、森を管理する側ではない。一つの仮説を深く掘りすぎる失敗、たとえば「Docker」の枝だけを延々と伸ばす失敗は、複数の枝を並行して保持することで構造的に避けられる。

図1：命題グラフを中心に、選択（アバウト）・適用（厳密）・剪定が循環する。人間は確信度の低い箇所だけを精錬し、その結果が世界モデルを通じて次の適用に効く。

### 4.3 一致の非推移性と確信度の減衰

アバウトな一致は推移的でない。A≈B、B≈C でも A≈C とは限らない。遷移のたびに一致判定が入ると、各ステップは妥当でもパス全体では意味がずれていく。これは「upper：甲皮」問題の連鎖版である。

対策として、一致判定は規則を適用する瞬間に限り、その類似度を枝の確信度に掛け合わせる。前提の確信度を p、各ステップの一致度を s とすると、n ステップ後の枝の確信度は次のようになる。

```latex
c_{\text{branch}} = \prod_{i=1}^{n} p_i \, s_i
```

これにより、曖昧な一致を重ねた枝ほど確信度が下がり、自然に剪定される。

## 5. 命題レベル・アテンションによる前提選択

第4節の手順1「適用可能な規則を集める」を、アテンションで実装する。単位をトークンから命題に持ち上げることで、語のレベルのif文を命題のレベルのif文に変える。

### 5.1 対応づけ

| Transformer \[10\] | 命題レベル・アテンション |
| --- | --- |
| Query：いまの位置のトークン | いま伸ばしている枝の先端の命題、または示したい結論 |
| Key：文脈中の各トークン | 世界モデル中の各規則の **適用条件** の埋め込み |
| Value：各トークンの情報 | その規則が導く結論 |
| 重み：どのトークンを参照するか | この局面でどの規則・前提を使うべきかの分布 |
| 位置エンコーディング | グラフ上の距離、どの推論パス上にあるか |

適用条件をKeyとして持たせることは、「選ぶ条件がない知識はないほうがまし」を機構として実現することでもある。条件を持たない知識は、どのQueryにも強く応答しない。

### 5.2 選択と適用の分離

アテンションの重みは「関係がありそう」の度合いにすぎない。そこで重みは選択にだけ使い、上位の候補に対する規則の適用は第4節の厳密な手続きが行う。重みはそのまま枝の事前確率となり、ビームサーチの剪定基準に入る。検索拡張生成 \[16\] も一種の選択だが、単位は文書であり、選んだ後の推論はLLMに任される点で異なる。

### 5.3 読める重み

トークンレベルのアテンションを見ても、なぜその出力になったかはほとんど分からない。命題レベルでは単位が意味のまとまりなので、「この結論は p3 と p7 に強く注意を向けた」と、重みをそのまま推論の根拠として表示できる。根拠が表示できれば、LLintで検査できる。

### 5.4 マルチヘッドの解釈

ヘッドごとに関係の型（causes、requires、contradicts）を分担させることができる。あるいはヘッドごとに異なる世界モデル（たとえば Hayek.wm と Keynes.wm）を割り当てれば、同じ問いに対してどの立場がどの前提に注目したかを並べて比較できる。

### 5.5 注意すべき性質

- **softmaxは必ず何かを選ぶ** 。関係する前提がない局面でも重みの合計は1であり、無関係な命題がもっともらしく選ばれる。「該当なし」を表すKeyを置くか、重みにしきい値を設ける。
- **関連性は妥当性ではない** 。アテンションは「そこから正しく導けるか」を測らない。だから選択と適用を分ける。

## 6. 人間による命題精錬

人間の判断は、重みではなく命題に記録すべきである。本節はその仕組みを、現行LLMの学習過程との対比で述べる。

### 6.1 RLHFとの対比

現行のLLMは、事前学習で粗い能力を獲得し、人間の選好による強化学習（RLHF）\[3\]\[12\] で振る舞いを調整する。この構想にも同じ二段階がある。LLMが命題候補を大量に出す段階が事前学習に、人間がそれを採用・棄却・修正する段階がRLHFに対応する。

決定的な違いは、修正の対象である。

|  | RLHF | 命題精錬 |
| --- | --- | --- |
| 修正の対象 | モデルの重み | 世界モデル中の命題と規則 |
| 影響範囲 | 全体に拡散し、特定できない | 局所的で、差分として見える |
| 取り消し | 困難 | 履歴から戻せる |
| 精錬者の立場 | 中立の顔をして混入する \[9\] | 署名付きの `.wm` として明示される |

RLHFで一つの振る舞いを直すと、別の振る舞いも変わる。迎合的になる傾向 \[9\] はその一例である。これは「upper：甲皮」問題をネットワークの内部で起こしているのに近い。

### 6.2 精錬の操作

人間の仕事は「AとBのどちらが良いか」に限られない。

- **条件を付ける** ：「upper → 甲皮」に「靴の文脈で」を足す。第1節の原則を人の手で充たす、最も価値の高い操作である。
- **分割する** ：曖昧な命題を二つの命題に割る。
- **統合する** ：別名を同一視し、アバウトな一致のしきい値を人が教える。
- **反例を付ける** ：全称的な規則に、それを破る事例をぶら下げる。

### 6.3 二重のループ

1. **明示的ループ** ：精錬された命題と規則は、そのまま世界モデルに入り、次の推論で使われる。
2. **暗黙的ループ** ：「LLMが出した候補」と「人間が直した結果」の組は選好データになる。これを使って、命題抽出器や一致判定器を後から学習し直せる。

RLHFには2しかない。人間が書いた原則でAIを調整する手法 \[13\] も、原則は最終的に重みへ溶ける。この構想では1と2が同時に回る。

### 6.4 人の負担を抑える

人間は比較のほうが絶対評価より速く、判断もぶれにくい。白紙から編集させるより、分解案を2〜3個並べて選ばせる。さらに、全候補を人に見せるのではなく、枝同士が矛盾した箇所や一致判定の確信度が低い箇所だけを人に回す（能動学習 \[8\]）。

## 7. 実装構想：LLint・LogicStudio・.wm

実装は三層からなる。検査器のLLint、それを統合する論理IDEのLogicStudio、そして差し替え可能な世界モデル形式 `.wm` である \[11\]。

### 7.1 LLint：UNIXパイプとしての論理Lint

LLintは小さなコマンドの組み合わせとして作る。

```bash
echo "風が吹けば桶屋が儲かる" \
  | llint --parse \
  | llint --edit --gui \
  >> pdic.jsonl
```

| サブコマンド | 役割 | 担い手 |
| --- | --- | --- |
| `--parse` | 自然言語から命題と関係の候補を出す。一つに決め打ちしない | LLM |
| `--edit` | 候補を確認し、採用・修正・棄却する。確定分だけを標準出力へ | 人間 |
| `--edit --gui` | 命題グラフを木として表示し、ドラッグ＆ドロップでノードを切り貼りし、ドロップダウンで関係を付け替える | 人間 |
| `--expand` | 指定した枝の中間命題を複数候補に展開する | LLM |
| `--check` | 文書や命題グラフを世界モデルと照合し、飛躍・矛盾・未充足の前提を報告する | 従来アルゴリズム |
| `--query` | 世界モデルを検索する | 従来アルゴリズム |

対話画面は端末やGUIに出し、確定したデータだけを標準出力に流す。これでパイプは汚れない。追記を前提とするため、保存形式はJSON配列ではなくJSON Linesとする。

linterがそのまま命題辞書のエディターを兼ねる点が要である。文章を読んで命題を抜き出し、人間が条件を補い、辞書に保存すると、次回のlintの精度が上がる。検査と精錬が同じ道具の上で循環する。

### 7.2 LogicStudio：論理IDE

プログラムに抽象構文木（AST）があるように、文章には論理の木がある。LogicStudioはそれを編集するIDEである。コードエディタが裏でASTを扱い、lintやリファクタリングを提供するのと同じ位置づけになる。

GUIで人が何度作り直しても、出力がJSONという境界さえ守れば、下流は動き続ける。GUIは人間のためのものであり、AIはJSONしか見ない。

### 7.3 .wm：世界モデル

命題と規則と適用条件の集合は、もはや辞書ではない。それを持つ人の世界の見方、すなわち世界モデルである。そこで形式名を `.pdic` から `.wm` に改める。

```bash
LogicStudio --wm KisaburoYamada.wm
logic-diff Hayek.wm Keynes.wm
```

推論エンジン（LLM）と世界観（`.wm`）を分離すると、次のことが可能になる。

- 同じ問いを異なる `.wm` で推論し、結論の違いを比べる。
- `diff` で二つの立場がどの命題で衝突しているかを特定する。
- `merge` で統合を試み、解消できない衝突を列挙する。

教育への応用も考えられる。学生は「ハイエクはこう言った」を暗記する代わりに、Hayek.wm がレポートのどこを問題視するかを、lintの警告として受け取る。学ぶ対象が結論から推論の構造へ移る。

## 8. 限界と今後の課題

ここまでの話はすべて構想段階で、以下はいずれも未検証である。

- **命題抽出の安定性** ：同じ文から毎回同じ命題が抽出される保証はない。抽出の揺れが、そのまま推論の揺れになる。
- **適用条件の記述コスト** ：「選ぶ条件」を人が書き足す作業は、ルールベース時代の辞書整備と同じ負担を再生産しうる。能動学習でどこまで減らせるかが鍵になる。
- **回帰** ：一つの精錬が既存の推論パスを壊しうる。編集のたびに保存済みの推論パスを再検証する仕組みが要る。そのためには、候補と判断の履歴を捨てずに全量保存しておく必要がある。
- **一致しきい値の設定** ：アバウトな一致をどこまで許すかは、領域ごとに異なるはずである。単一のしきい値では足りない可能性が高い。
- **確信度の較正** ：LLMが出す確信度の数値は、そのままでは確率として較正されていない。第4.3節の掛け算が意味を持つには較正が要る。
- **署名のない世界モデル** ：誰かが精錬した `.wm` が、無署名の「標準辞書」として流通する危険がある。来歴の記録を形式の一部にすべきである。

検証の第一歩としては、小さな領域（たとえばソフトウェアの導入手順）で、LLM単体とLLint構成を比較することが考えられる。比較の軸は、正解への到達率、推論の飛躍の検出率、人間が介入した回数である。

## 9. おわりに

この記事では、推論を命題グラフ上の遷移として表現し、その遷移を選択と適用に分ける設計を提案した。選択はアテンションによって近似的に、適用は従来アルゴリズムによって厳密に行う。人間の判断は重みに溶かさず、命題として署名付きで残す。

この設計の根にあるのは、ルールベース機械翻訳の時代から一貫した問題意識である。曖昧性は掛け算で増える。条件のない知識は害になる。意味は文脈である。Transformerはこれらの問題を否定したのではなく、条件分岐をベクトル空間に移すことで、実用の範囲に持ち込んだ。

その上で残る課題は、知識を増やすことではなく、知識を選ぶ条件を育てることである。LLint、LogicStudio、`.wm` は、その条件を人間とAIが共同で育てるための器として構想した。

> LLMが枝を生やし、古典アルゴリズムが森を管理し、人間が森の地図を描く。
