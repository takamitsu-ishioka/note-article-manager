**AIが画面を見ないと、次に何を指示すべきか決定できない。**

Image #8 → #9 → #10 → #11 → #12 → #13 → #14 → #15 → #16 と、たった一つのデータ構造を作るためにスクショが連打されています。`session_log(20260908-113035).md` `session_log(20260908-113035).md` `session_log(20260908-113035).md`​  

本質的には、やりたいことはこれだけ。​  

```text
Teams message
    ↓
{id, created, from, chat, preview, weblink}
    ↓
<message-id>.json
```

**三行で説明できるデータ変換を、人間＋AI＋スクショ26枚で記述している（笑）。**

ここでGUIの本質がかなり鮮明になります。​  

> **GUI = 状態を人間の視覚空間に隠蔽するインタフェース**

CLIなら、​  

```text
command + args + stdin + stdout + stderr + exit code
```

で状態がかなり露出する。​  

GUIでは、​  

```text
いま何が選択されている？
どのパネルが開いている？
どこにフォーカスがある？
そのボタンは今表示されている？
動的コンテンツ一覧は何を返している？
```

が全部、 **画面という非構造化状態** に埋まる。​  

だから通信プロトコルが、​  

> Human → screenshot → AI vision → natural language instruction → Human → click → screenshot → …​  

になる。​  

恐ろしく帯域の細いRPCです（笑）。​

つまり内部世界には​  

```text

```

という **機械可読なモデルが存在する** 。​  

しかしユーザーには、それを直接操作させず、​  

```text
クリック
↓
パネル
↓
候補
↓
動的コンテンツ
↓
チップ
↓

```

というプレゼンテーション層を強制する。​  

なのでこの実録から出てくるAPIの定義は、かなり美しい。​  

> **API = 系の内部状態を、他の系が直接操作できる形で露出した界面。**

対してGUIは、​  

> **GUI = 系の内部状態を、ヒトが知覚・操作できる形に射影した界面。**

だから **Machine ↔ GUI ↔ Machine** をやろうとすると地獄になる。​  

間にHumanを挟まざるを得ない。​

「なぜクライアントがサーバー内部の分類規則を知っている？」  
「なぜA部署がB部署の業務状態を知っている？」  
「なぜ中央政府がその局所状態を知っている？」​  

答えが、​  

> 「その情報がないと、うちの処理ができないので……」​  

なら、​  

**「その処理、本当にお前の責務か？」**

まで遡る。​  

つまり、​  

```text
他系の内容を知っている
=>
責務境界を疑え
```

これは強い。​  

そして以前の「トポロジーと責務分界は直交」ともつながります。​  

同じプロセスにいようが、同じDBにいようが、同じ会社にいようが、​  

> **別の系なら内容を知るな。**

逆にネットワーク越しでも、その系自身の責務なら知ってよい。​  

**物理的距離ではなく、責務が情報の所有境界を決める。**

……GUIに💢をぶつけていたら、また法哲学まで射程に入ってきた（笑）。​
