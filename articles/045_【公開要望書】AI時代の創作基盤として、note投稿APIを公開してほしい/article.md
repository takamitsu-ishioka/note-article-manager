# 【公開要望書】AI時代の創作基盤として、note投稿APIを公開してほしい

> 本稿は、note運営へすでに送付した要望を、広く共有するために公開するものです。生成AIを活用して創作する一人のユーザーからの、公開要望書としてお読みください。

## 要旨

noteに、外部ツールから**下書き記事の作成・更新と画像のアップロード**を行える公式APIを公開していただきたいです。

これは単なる「投稿を自動化したい」という要望ではありません。

生成AIの急速な普及によって、文章や画像を作る工程そのものが大きく変わりました。現在は、AIとの対話から記事本文を作り、Markdownへ変換し、タイトル画像や本文中の画像まで生成するところまで、個人でも容易に自動化できます。

ところが最後の、

**「完成した記事と画像をnoteへ持っていく」**

という工程だけが、人間によるブラウザ操作として残ります。

いま必要なのは「AIに記事を書かせる機能」ではありません。

**AIを含む外部の創作環境とnoteを接続する、細く安定した公式インターフェースです。**

これは将来あると便利な機能ではなく、生成AIによって創作環境が急速に変化している**今、喫緊に整備すべき基盤**だと考えます。

## 現在すでに起きていること

私自身、現在次のようなワークフローでnote記事を制作しています。

```text
ChatGPTとの対話
      ↓
ChatGPT Exporter
      ↓
Markdown
      ↓
AIエージェント
      ├─ note向け本文整形
      ├─ タイトル・ハッシュタグ調整
      ├─ タイトル画像生成
      └─ 本文用画像生成
      ↓
完成したMarkdown + 画像
      ↓
【ここから人間がブラウザで作業】
      ↓
noteへコピー
画像をアップロード
画像を適切な位置へ配置
表示確認
      ↓
公開
```

これは構想ではなく、すでに実際に動いているワークフローです。

たとえば最近の作業では、AIエージェントにMarkdown化された対話を渡すだけで、本文の整形、話者見出し、引用、改行、ハッシュタグの確認に加え、タイトル画像の生成と1280×670への寸法調整まで完了しています。つまり、noteへ投入する直前の成果物までは機械的に生成できています。

残っている大きな手作業が、noteとの接続部分なのです。

## なぜこれが「喫緊の課題」なのか

生成AI以前、文章を書く主体は基本的に人間でした。

人間が文章を書き、人間がブラウザを開き、人間が投稿する。その世界では、Webブラウザ上の優れた編集UIがあれば十分でした。

しかし現在、創作物の生成主体は、

**人間単独**

から、

**人間 + AI + 各種ツール**

へ急速に変わっています。

重要なのは、AIがnoteの中に入ることではありません。

利用者が自分に合ったAI、自分に合ったエディタ、自分に合った画像生成環境、自分に合った自動化ツールを組み合わせ、**noteの外側に独自の創作環境を作り始めている**ことです。

すると、プラットフォームに求められる役割も変わります。

従来：

```text
人間 → noteの編集画面 → note
```

現在：

```text
人間
  ↓
AI・エディタ・画像生成・自動化
  ↓
完成した記事
  ↓
？？？
  ↓
note
```

この `???` を公式に提供しない状態が長く続けば、利用者はブラウザ自動操作、非公式API、独自スクレイピングなどに向かいます。

それは利用者にとって不安定であるだけでなく、note側にとっても望ましい状況ではないはずです。

だからこそ、**非公式な自動化手段が乱立する前に、公式で小さく安全なAPIを定義する必要がある**と考えます。

## 必要なのは巨大なAPIではありません

最初からnoteの全機能をAPI化する必要はないと思います。

私がまず必要としているのは、ほぼ次の二つだけです。

1. **下書き記事を作成・更新するAPI**
2. **記事で使用する画像をアップロードするAPI**

たとえば概念的には、

```text
POST /assets
POST /drafts
```

程度から始められます。

あるいは `multipart/form-data` 等を利用して、

```text
POST /drafts

- title
- body
- title_image
- images/*
```

のように、「一つの記事」という複合オブジェクトを一度に渡せても便利です。

具体的なHTTP設計はもちろんnote側で決めるべきですが、重要なのは、

> **完成した記事を外部の創作環境からnoteの「下書き」へ渡せる**

という契約を作ることです。

## 「自動公開」は必要ありません

安全性やスパム対策を考えると、初期段階では**記事を公開するAPIすら不要**だと思います。

外部ツールができることを、

```text
外部ツール
   ↓
下書き作成・更新
画像アップロード
   ↓
note編集画面
   ↓
人間が確認
   ↓
「公開」を押す
```

までに制限すればよいからです。

これなら最終的な公開判断は従来通り人間に残ります。

AIエージェントによる大量自動投稿を可能にするのではなく、**創作工程と公開工程の間に公式の搬入口を作る**という考え方です。

## noteにとっても重要な基盤になる

生成AI時代には、「どのAIを使うか」は利用者によって異なります。

ChatGPTを使う人もいれば、ClaudeやGeminiを使う人もいます。ローカルLLMを使う人、自作のエージェントを使う人、将来登場する別のツールを使う人もいるでしょう。

note自身がそのすべてに対応する必要はありません。

むしろ、

> **創作環境は利用者に任せ、noteは安定した投稿インターフェースを提供する。**

という分業のほうが、長期的には強いのではないでしょうか。

APIがあれば、ChatGPT、Claude、各種エディタ、CMS、個人開発ツールなどからnoteへつながる新しいエコシステムが、note自身の開発コストをかけずに育つ可能性があります。

## 結論

生成AIによって、コンテンツ制作のボトルネックはすでに「文章を書くこと」から別の場所へ移り始めています。

私の環境では、

**対話 → Markdown → 本文整形 → 画像生成**

まではすでにAIエージェントで処理できます。

ところが、

**完成物 → note**

だけが人間による手作業です。

この断絶は今後、生成AIを活用するユーザーが増えるほど大きな問題になると思います。

だからこれは「いつかAPIがあれば便利」という要望ではありません。

**AI時代の創作プラットフォームとして、外部の創作環境と接続するための公式インターフェースを今のうちに定義しておくべき、喫緊の基盤整備課題です。**

巨大なAPIは必要ありません。

まずは、

**「画像をアップロードできる」  
「完成した記事を下書きとして渡せる」**

この二つだけでも、創作者の世界は大きく変わります。

ぜひ、公式投稿APIの策定・公開をご検討ください。
