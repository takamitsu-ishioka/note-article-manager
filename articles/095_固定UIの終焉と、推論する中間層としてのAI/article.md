# 固定UIの終焉と、推論する中間層としてのAI

![](nb7c653e679cc_36d6cfacdf948ac046e9251091cad6d0.png)

## きっかけの直観

「固定的ユーザーインタフェース」の時代は、もう終わりに近いのではないか。

ユーザーとビジネスロジックの間に入るのは、生成AI——そしてさらに後には「論理連想統合AI」と呼べるような存在——になるのではないか。

理由はシンプルだ。ユーザーによって最適なユーザーインタフェースは違うから。

現在のUIは「平均的なユーザー」という幻想に最適化されている。専門家と初心者では最適な情報密度がまったく違うし、認知・視覚・運動能力の個人差もある。文化や思考様式の違いもある。固定UIはそれらを一律に無視している。

すでに兆候はある。「ExcelでVLOOKUPをやりたい」とClaudeに話しかける人が増え、ExcelのUIを直接学ぶ必要性が薄れている。UIをAIが抽象化し始めているのだ。

## 論理連想統合AIとは何か

では、現在の生成AIを超えた「論理連想統合AI」とはどんな構造か。

私が考えているのは、二つのモジュールの組み合わせだ。

**因果論理モジュール（メインルーチン）** 命題の遷移網を生成しながら探索する。単なるテキスト生成ではなく、命題レベルのグラフ構造を明示的に保持・操作する。

**トランスフォーマーによる推論機** 次のノードや前のノードの「確率付き候補リスト」を生成する。現行LLMを推論エンジンとして流用できる部分だ。

現在のLLMが「次トークンの確率」という線形・局所的な処理に留まるのに対し、このアーキテクチャは命題グラフ上の探索を行う。

## 探索アルゴリズムの設計

探索の方式はマルチスレッド（マルチプロセス）による並列・深さ優先探索だ。

経路の評価には**エッジ確率の対数の和**を使う。

```
経路の尤度 = Σ log P(edge_i)
```

確率の積は経路が深くなるにつれてアンダーフローするが、対数和にすることで数値的に安定する。情報理論的にも自然な解釈ができる。順位か閾値で枝刈りを行い、有望でない経路を積極的に捨てる。

## 共有メモリによる協調

並列探索の問題は、スレッド間で同じ経路を重複探索する無駄だ。これを防ぐために二つの共有構造を持つ。

- **探索済みキャッシュ**：既探索ノード・エッジの尤度を保存。再訪問時は即座に返却。
- **上位経路テーブル**：現時点のトップN経路をランキングで保持。

上位経路テーブルが特に重要で、「現在のトップNの最低尤度」を枝刈り閾値として動的に使える。探索が進むにつれて閾値が自動的に厳しくなる。これはBranch and Boundそのものだ。

## ユーザーが探索の舵を握る

終了条件はどう決めるか。最も現実的なのは、ユーザーとの対話で決めることだ。

```
システムが探索を走らせながら上位経路（候補）をユーザーに提示
  ↓
「これで十分」「もっと探索して」「別の方向へ」
  ↓
ユーザーの判断が終了条件 or 探索方向の修正になる
```

ここで最初の直観に戻る。

UIが消えるのではない。**命題グラフの探索ナビゲーション自体がUIになる**のだ。

ユーザーによって最適な推論経路も違う。だから対話で動的に決める。固定UIの終焉という直観と、このアーキテクチャの設計は、根っこで一致している。

## 残る問い

言語インタフェースには「見て気づく・触って発見する」というアフォーダンスがない。ユーザーが自分の欲しいものを正確に言語化できない場面で、このシステムはどう振る舞うか。

AIが実行した結果を、ユーザーはどう検証するか。固定UIには「見れば状態がわかる」という透明性があった。

これらはまだ解かれていない問いだ。ただ、命題グラフの上位経路を可視化するという方向に、答えの一端があるような気がしている。
